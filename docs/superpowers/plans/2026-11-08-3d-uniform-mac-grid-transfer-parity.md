# 3D Uniform MAC Grid and Transfer Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qualify the uniform sparse 3D MAC topology and complete-support transfers against independent analytic CPU and CUDA fixtures.

**Architecture:** Sorted signed 4³ block keys define one physical owner per face. A checked host stencil resolves all owned slots before transfer work begins. CPU FP64 establishes the reference and integer accumulation contract, and CUDA executes transfer arithmetic and reductions over the validated sparse mapping.

**Tech Stack:** C++20, CUDA, Abseil, GoogleTest, locked Python 3.13/uv, Conan 2, CMake/Ninja, pinned Lean/mathlib.

**Spec:** [FluidiTy design](../specs/2026-11-07-fluidity-design.md), §§4.1–4.2, 5.1, 11.3, 13 and 15. See the [M1 roadmap](2026-11-08-m1-uniform-3d-liquid-roadmap.md).

## Global Constraints

- Use SI, uniform quadratic B-splines on each shifted face lattice, and one staggered MAC velocity representation. A block owns 64 cells and 3×64 low faces.
- The common particle bin is B_d=floor((x_d/h−1.5)/4) relative to grid origin at the last sort. With displacement ≤0.5h per axis the shared tile is [4B_d,4B_d+8). Check actual inclusion and allocated ownership before any write.
- Quantize each contribution before summation. Q=rint(c/s_channel), with finite c and |c/s|≤2^(62−n_cap). No saturation. Rounding error has its own budget.
- Liquid particle stress is zero. The stress-force channel therefore sums zero. Physical viscosity belongs to the grid in its milestone.
- AGENTS.md governs C++20, names, API comments, mandatory braces, repository formatting and checked Status/StatusOr interfaces. Keep host-only facilities outside device code.
- Use locked uv (≥0.13.7, Python 3.13), Conan 2, the committed locks and Ninja presets. Format with clang-format 19.1.5. Requalify the Windows tuple and keep the compiler guard active. Reference GPU compute capability 12.0, explicit 120-real;120-virtual. Real Debug and Release CUDA plus named-pipe Release memcheck are required.
- This slice uses complete support and FP64 for comparison. Boundary masks, old/new ghost construction, normalized velocity validity, history policy and advancement are subsequent slices. Pressure and topology transactions are subsequent slices. The initial transfer operators are bounded parity entry points; production substeps must reuse preallocated arenas.
- Retain each task's expected failing assertion, green focused/full results, review package and fixes in ignored `out/m1/` or the ignored skill workspace. Run a fresh implementer and independent task reviewer per task. Commit task and review fixes separately. Do not advance with unresolved findings.

## Review Focus

- A positive-side block is absent even when its face has zero weight. Reject before publication (Task 1).
- Negative coordinates around -4, 0 and signed index limits must use floor and widened arithmetic (Task 1).
- A later particle can reject after earlier scratch work. Preserve all public outputs and reject aliasing up front (Task 2).
- Test actual affine contribution range, signed ties, exact capacity boundary and one-quantum/magnitude excess (Task 2).
- Successful CUDA transfer launches must prove the compiled image with a receipt. A device-specific rejection preserves output sentinels (Task 3).
