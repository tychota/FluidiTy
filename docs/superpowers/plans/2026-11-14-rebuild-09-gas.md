# Rebuild Gas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the gas module of the rebuild (fire and smoke): the gas amounts per cell with their try and
commit, the gas law, burn and lift formulas, keyed sources and wind, the gas solve `SolveGas` (geometry from the
liquid's, starting amounts, sources, burn, lift, background pressure per blob, added volume, pressure's solve,
flow of amounts), marker upkeep, what the liquid reads of the gas, the snapshots, the capability check, on CPU
and (compiled, not run) GPU, and tested beside liquid. Owner answer A15 (Tasks 29, 30): when the gas solve's
working buffers do not fit the GPU, it runs batch by batch through pressure's `SolveBatches`, agreeing with the
one-piece solve within its tolerance.

**Architecture:** Folder `native/fluidity/gas/`, namespace `fluidity::gas`. Each operation has one public
CPU-only header and private `_cpu.cc` / `_gpu.cu` files; every per-cell and per-face formula lives in a shared
`FLUIDITY_CPU_AND_GPU` header that the CPU loop and the GPU function both call. Gas reuses pressure's
`GeometrySnapshot`, `BuildPressureEquations` and `SolvePressure` on a second `PressureBuffers` instance. All
arrays are `grid::CellValues` / `FaceValues` bound to a grid version; working buffers live in `GasBuffers`, built once.
Every scene total is one partial per cell block in the grid's block order, then `math::TreeSum`.

**Tech Stack:** C++23 host, CUDA C++20 device, CMake presets + Ninja, Conan 2 (GoogleTest), uv, Typst + CeTZ
(method paper), clang-format and clang-tidy 23.1 (the versions `pyproject.toml` pins). No Python reference and no Lean proof (design section 7).

**Spec:** `docs/superpowers/specs/modules/09-gas-design.md` (its section 3 is the contract) and the programme
design `docs/superpowers/specs/2026-11-13-production-rebuild-design.md` (sections 6, 7, 8, 8a). Both in the
`main` checkout, read-only. Also read there: `modules/owner-answers.md` (A2, A8, A10), `modules/shared-interface.md`,
`modules/plan-decisions.md`, section 3 of `05-pressure-design.md`, 3.1 to 3.7 of `02-grid-design.md`, 3.1 and
3.5 of `03-particles-design.md`, section 3 of `04-transfer-design.md`, 3.2 of `01-contact-design.md`, and the
step's stage order in `10-step-design.md` section 5.3 (what `TryStep` will call; the tests here imitate it).

   `293.15000000000003`, not `293.15`, so a lift computed from temperature would push still air. Pinned:

   held at atmosphere, never fail `kBackgroundPressureOutOfRange`. Pinned:
   `ComputeGasAddedVolumeRate, HeldBlobAboveRange_IsNotAFailure` in Task 16.
