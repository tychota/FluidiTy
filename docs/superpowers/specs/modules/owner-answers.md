the `rebuild` branch.

| A14 | Output file formats | Use open formats as much as possible: Alembic, USD and OpenVDB. FluidiTy's own array file is used only for what no open format fits: the saved state and internal run records. Where two open formats could carry a product, pick the one Blender's native reader consumes fully (velocity for motion blur, per-point and per-face attributes, a file sequence), proven by a test in Blender, and prefer USD when both pass. |
| A15 | Batched runs | The pressure, viscosity and gas solves are also batched, so a scene far larger than GPU memory can run (limited by CPU memory). A batched run agrees with a one-piece run within the solver's tolerance, not byte for byte; each mode is repeatable on its own (same input, same bytes). This replaces "the solves are not batched" and the byte-identical test between modes. (2026-11-14) |

| A17 | Grid build on GPU runs | The grid is built on the GPU in a GPU run; only a small status record comes back. (2026-11-14) |
